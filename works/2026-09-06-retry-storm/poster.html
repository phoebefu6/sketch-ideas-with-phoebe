Retries don't add.
They multiply.

One user action. Three layers, each configured to retry three times - four attempts apiece. Sixty-four calls arrive at the endpoint that was already failing, which is the reason all of them exist.

Why it multiplies

Attempts compound as a product, not a sum: three layers at four attempts each is 4 x 4 x 4, not 3 + 3 + 3. Google's SRE book draws it with a database - "a single user action may create 64 attempts (4³)". Swap the database for a model endpoint and the arithmetic is unchanged.

The layer you didn't configure

You wired two retry layers on purpose. The third came free: the Anthropic Python SDK auto-retries connection errors, 408, 409, 429 and 5xx with exponential backoff, at a default max_retries = 2 - up to three attempts per call. It is on until you set it to 0.

The fix, already published

Retry at a single point in the stack (Amazon Builders' Library). Cap attempts per request, then add a budget: SRE's per-client rule retries only while the retry ratio stays under 10%, holding load growth to 1.1x instead of ~3x.
